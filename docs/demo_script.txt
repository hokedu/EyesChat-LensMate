# EyesChat-LensMate Demo 口播文案

## 开场（10秒）
大家好，我是本次项目的开发者。今天我带来的是 EyesChat-LensMate，一款 AI 视觉对话助手。它能够"看见"我面前的画面，"听见"我说的话，并且用语音给我回复。

## 用户故事（30秒）
在设计这个项目的时候，我列了 15 个用户故事。最终完整实现了其中 12 个。最核心的有这五个：

第一，作为用户，我可以一键打开摄像头，让 AI 看到我面前的画面。
第二，我可以用语音和 AI 自然对话，不需要打字。
第三，AI 能够基于当前画面回答我的问题，比如桌子上有什么、这个工具怎么用。
第四，AI 的回复是语音朗读出来的，我可以边做事边听。
第五，当我再次说话的时候，AI 会立刻停止朗读，开始听我说话。

此外我还实现了隐私模式、对话历史查看、多轮上下文记忆，以及一个实时展示 Token 消耗和费用的仪表盘。

## 功能演示（40秒）
现在我来演示几个核心功能。

演示一：我先打开摄像头，然后对着它说话。"帮我看看桌上有什么。"AI 现在看到了我桌面上的物品，正在用语音回复我。

演示二：多轮对话。我问"刚才那个红色工具是什么？"AI 能回忆之前看到的内容，告诉我那是螺丝刀。

演示三：语音打断。AI 正在说话的时候，我直接开始说话，它立刻停了下来。

演示四：隐私模式。我点击隐私开关，系统提示"隐私模式已开启，数据不会保存到服务器"。

演示五：实时成本仪表盘。页面底部可以看到 Token 消耗数量、费用估算、预算使用进度条和帧上传计数。

## 成本控制（30秒）
这个项目的另一个重点是成本控制。我采用了这样几个策略：

第一，语音识别。我用的是浏览器自带的 Web Speech API，完全免费，不需要调用任何云端接口。

第二，摄像头帧采样。我只截取 320x240 的低分辨率画面，每秒不到两帧。比起直接把 30 帧的完整视频流发给 AI，帧数减少了 94%，每一帧的 Token 消耗从三千多降到了两百多。

第三，对话历史裁剪。我只保留最近五轮对话的上下文，避免每次请求的输入 Token 不断膨胀。

第四，AI 回复长度限制。我设了 200 个 Token 的上限，防止 AI 说太多。

整体算下来，如果用 GPT-4o 的官方 API，单次交互的成本大约是 0.0025 美元。而我现在用的是硅基流动的 Qwen VL 模型，在免费额度内跑，几乎不花钱。
