# EyesChat — AI 视觉对话助手 完整设计方案

## 1. 项目概述

EyesChat 是一款基于 GPT-4o Vision 的 AI 视觉对话助手。用户打开摄像头与麦克风后，AI 能够实时"看到"摄像头画面中的内容、"听到"用户的语音，并给出自然流畅的图文回应。核心设计重点：视觉理解准确性、语音交互自然度、端云协同成本控制。

## 4. 核心功能模块

### 4.1 智能帧采样系统（成本控制核心）

```
帧捕获 (600ms定时器)
    │
    ▼
Canvas: 640×480 → 320×240 下采样
    │
    ▼
JPEG 压缩 quality=0.6
    │
    ▼
Base64 编码 (~15-25KB/帧)
    │
    ▼
WebSocket → {"type":"frame","base64":"..."}
    │
    ▼
后端更新最新帧 (仅保留1帧，不累积)
```

**关键设计**：
- **固定 2fps**（每 600ms 一帧），平衡实时性和成本
- **低分辨率** 320×240，GPT-4o `detail: "low"` → 每帧仅 ~340 tokens
- **仅保留最新帧**，不堆积历史帧 → 每次请求的 Vision Token 固定
- 相比 15fps 原始视频流，**帧量减少 85%，Token 消耗减少 90%+**

### 4.2 语音流水线

```
用户说话 → Web Speech API (端上，免费)
    │
识别的文本 → 输入框实时显示
    │
1200ms 静音检测 → 自动发送（或手动按回车/发送按钮）
    │
    ▼
WebSocket → {"type":"transcript","text":"..."}
```

**关键设计**：
- **端上语音识别**（Web Speech API）：免费，无云端成本
- **静音检测自动发送**：1.2 秒静音后自动提交，手不离口
- **用户可打断**：继续说话自动覆盖等待中的提交
- **兜底文字输入**：语音不准确时可手动纠正

### 4.3 多模态推理引擎

```
请求组成：
┌─────────────────────────────────────┐
│ System Prompt：角色设定 + 行为规则   │
├─────────────────────────────────────┤
│ Conversation History (最近N轮)       │
├─────────────────────────────────────┤
│ 用户消息 = 最新帧(1张) + 语音转文字   │
└─────────────────────────────────────┘
         │
         ▼
    GPT-4o Vision
    stream=True
    max_tokens=300
         │
         ▼
    流式输出 text chunks
    最终 meta (token统计 + 费用)
```

**上下文管理**：
- 最多保留 20 轮对话
- 50,000 Token 总预算，超出即停止
- 每次请求包含：System（约 200 tokens）+ 对话历史 + 1帧（~340 tokens）+ 用户文本

### 4.4 实时成本控制仪表盘

| 指标 | 显示 | 来源 |
|------|------|------|
| Token 消耗 | 累计值 | 每次 meta 消息累加 |
| 估算费用 | USD（6位小数） | 按 GPT-4o 单价: $0.0025/1K 输入, $0.01/1K 输出 |
| 预算使用率 | 进度条 + 百分比 | Token / 50,000 |
| 颜色编码 | <50% 紫色, 50-80% 黄色, >80% 红色 | 直观告警 |
| 帧计数 | 累计上传帧数 | frame_ack 消息 |
| 轮次 | 已完成的对话轮数 | get_status 响应 |

## 5. 运营成本控制策略

### 已实现的成本控制

| # | 策略 | 实现 | 效果 |
|---|------|------|------|
| 1 | **低分辨率帧** | 320×240 + detail:"low" | 每帧 ~340 tokens（vs 高分辨率 ~2000+） |
| 2 | **2fps 帧率** | 每 600ms 发送 | 帧量减少 85% |
| 3 | **仅保留最新帧** | 后端只存 1 帧 | 每次请求不累积画面 Token |
| 4 | **JPEG 压缩** | quality=0.6 | 帧大小 ~20KB（vs 原图 200KB+） |
| 5 | **会话 Token 预算** | 50,000 Token/会话 | 单会话成本上限 ~$0.25 |
| 6 | **轮次限制** | 最多 20 轮 | 进一步限制最大成本 |
| 7 | **流式响应** | stream=True | 不额外增加成本 |
| 8 | **端上语音** | Web Speech API | 语音识别零成本 |
| 9 | **实时费用显示** | Cost Dashboard | 用户可感知成本 |

### 单次交互成本估算

```
输入：200(系统) + 50(历史平均) + 340(帧) + 20(用户文本) = ~610 tokens
输出：~100 tokens
单次费用 = (610/1000 × 0.0025) + (100/1000 × 0.01)
         = $0.0015 + $0.0010
         = $0.0025
每会话(按10轮) ≈ $0.025
50,000 Token 预算 ≈ 50-70 次交互
```

## 6. API 设计

### WebSocket 端点 `/ws/chat`

#### 客户端 → 服务端

| type | 字段 | 说明 |
|------|------|------|
| `frame` | `base64` | JPEG 帧的 base64 编码 |
| `transcript` | `text` | 用户语音转文字结果 |
| `store_assistant` | `text`, `token_count` | 客户端确认 AI 回复后存储 |
| `get_status` | — | 查询当前会话状态 |
| `ping` | — | 心跳 |

#### 服务端 → 客户端

| type | 字段 | 说明 |
|------|------|------|
| `session_start` | `session_id`, `config` | 连接确认 + 配置下发 |
| `frame_ack` | `frame_count` | 帧接收确认 |
| `stream_start` | — | AI 开始生成回复 |
| `text` | `content` | 流式文本块 |
| `meta` | `content(JSON)` | Token 统计 + 费用估算 |
| `stream_end` | — | 回复结束 |
| `status` | 多个字段 | 会话状态快照 |
| `budget_exhausted` | `message` | 预算耗尽告警 |

### 交互流程

1. 用户点击「开始对话」→ WebSocket 连接建立
2. 点击 📷 → 浏览器请求摄像头权限 → 画面开始显示
3. 点击 🎤 → 浏览器请求麦克风权限 → Web Speech API 启动
4. 用户对着摄像头说话 "这是什么水果？" → 1.2 秒后自动发送
5. AI 收到帧 + 文本 → 流式回复 → 对话区实时显示文字
6. 底部面板实时更新 Token 消耗和费用

## 10. 创新点总结

1. **实时 Cost Dashboard**：面试官可以直接看到 Token 消耗和费用实时变化
2. **端云协同成本控制**：2fps + 320×240 + JPEG 0.6 + detail:low = 极致降本
3. **纯浏览器端语音识别**：Web Speech API，零成本
4. **会话级预算保护**：50K Token 上限，防止 API Key 费用失控
5. **流式视觉对话**：用户看到 AI 逐字回复，体验流畅
